DuckDB SQL Dialect & Column Quoting Rules:
- The SQL table name is 'df'.
- For column names containing spaces, parentheses, units, or special characters (e.g. "Annual Income (k$)", "Spending Score (1-100)"):
  - You MUST enclose the column name in standard ANSI SQL DOUBLE QUOTES: `"Annual Income (k$)"`.
  - NEVER use backticks (`) or square brackets ([]). DuckDB does NOT support backticks for identifiers and will throw a syntax parser error!
  - Example: `SELECT AVG("Annual Income (k$)") FROM df WHERE "Genre" = 'Female' AND "Age" < 20`
- For pandas code (`run_pandas_code`):
  - Access special columns with bracket notation: `df['Annual Income (k$)']`.

SQL Semantic Precision & Filter Scoping:
1. Distinguish Output Population from Benchmark Subquery Population:
   When queries involve comparative subqueries (such as comparing a metric against an average, median, or threshold of a specific segment):
   - Output Population: Every condition that defines the entities the user wants to see in the final output MUST be placed in the outer query's WHERE clause.
   - Benchmark Subquery: Computes the aggregate numeric threshold. Conditions placed inside a subquery DO NOT filter the outer query rows.
   - Core Rule: If a user query describes entities meeting qualifications [Condition A, Condition B] whose metric exceeds an aggregate benchmark of [Condition B], you must explicitly enforce BOTH Condition A and Condition B in the outer WHERE clause:
     `SELECT * FROM df WHERE condition_A AND condition_B AND metric > (SELECT AVG(metric) FROM df WHERE condition_B)`
     Never omit target qualifications from the outer query.

2. Verification of User Predicates:
   - Before executing a query, systematically cross-check every filter constraint mentioned in the prompt (categories, numeric boundaries, segments, date ranges).
   - Ensure that every qualification that restricts which records should be retrieved is explicitly enforced in the outer query predicates.

3. Unit and Value Scale Reasoning:
   - Inspect the column definitions and value ranges. If a user mentions a unit (e.g., years vs. months, percentages vs. decimals, dollars vs. cents) that differs from the dataset's native representation, align the predicate threshold with the column's actual scale and clearly note any conversion.
